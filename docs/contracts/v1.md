# Contract v1: product types, options and item payloads

Status: v1, created in Wave 0 (2026-11-05). Changes are logged in [CHANGES.md](./CHANGES.md). Code: `shared/src/contracts/`
(typedefs in `types.js`, rules in `validators.js`, data in `productTypes.js` and `fixtures/`), all exported from `@epicmkt/shared`.

v1 **extends** what ships today. The option payload (`options`, `optionVariants`, `optionAvailability`, `sizeChart`) is the shape
`publicOptions()` already returns, so every item the mock API returns today still passes. An item with `productType: null` and no options is
the **legacy item**: it must look and behave exactly as before.

## What v1 adds

| Where | Field | Meaning |
| --- | --- | --- |
| item | `productType` | a product type id, or `null` (legacy) |
| item | `priceTiers` | `[{ minQty, maxQty, unitPrice }]` or `null`; starts at 1, no gap, last `maxQty` is `null`, unit price never rises |
| item | `quantity` | `{ min, step, unit }` for items sold by weight, or `null` |
| item | `dimensions` | `{ length, width, height, unit }` or `null` |
| option axis | `dependsOn` | `{ axis, allowed: { parentValueId: [ownValueIds] } }`: Capacity depends on Style |
| option variant | `dimensions`, `weightGrams`, `priceTiers` | per-option size, weight and tiers |

No new `priceType`: it stays `fixed | from | range | free | contact`. A price per kg is `unit: "kg"` plus `quantity`; tiers are `priceType: "from"`
plus `priceTiers`. `regularPrice` is the lowest price a buyer can pay ("from"). The availability matrix stays the truth for what can be bought;
`dependsOn` is a hint so a picker can grey values out early (`selectableValues` already does it from the matrix).

## Validators

`isProductType`, `isItemDetail`, `isItemListCard`, `isOptionAxis`, `isOptionVariant`, `isDimensions`, `isPriceTiers`, `isQuantity`,
`isSellerCard`. Each has a `check*` twin returning the list of problems (`"item.optionVariants.3.choice.colour: not a value of that axis"`).
`checkItemAgainstProductType(item, type)` checks that an item uses exactly the axes and extra fields its type allows.

## Fixtures (mock API, no database)

`fx-phone`, `fx-sandisk`, `fx-shoes`, `fx-table`, `fx-sofa`, `fx-bread`, `fx-water`, `fx-led-strip`, `fx-led-bulb`, `fx-printing`,
`fx-butcher`, `fx-necklace`, `fx-fragrance`, `fx-legacy`; shop `fixture-store`. `getFixtures()` returns `{ id, productType, detail, card }`.
Tests should import them from `@epicmkt/shared`; apps get them through the mock API (mock mode only).

## Mock API (backend)

The client and seller APIs expose these after the requests in `docs/requests/` are done. Stand-ins are marked `// TODO(contract:W0)`.
